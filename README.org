* Overview

** Description

The *macros* in Org allow you to add text or code to an Org document that will be
*expanded during export*: the text between the 3 pairs of accolades is expanded
so that readers can see it in the exported versions of the document.

Some people (such as me) use it to construct complex HTML or LaTeX code.

** Objectives

Using macros allows you to *insert dynamic content* or *add extra functionality* in
exports of an Org document.

** Features

These [[https://github.com/fniessen/org-macros][Org-macros]] have been tested for HTML exports.

FIXME They will be soon made available for PDF exports.

** Usage

Once you've cloned [[https://github.com/fniessen/org-macros][Org-macros]], many macros will be ready to use within your Org
files.

You can *invoke macros* anywhere in the document (even in code examples).

Examples:

- With no arguments:

  #+begin_example
  {{{macro-name}}}
  #+end_example

- With arguments:

  #+begin_example
  {{{macro-name(arg1,arg2)}}}
  #+end_example

** Clearpage macro
:PROPERTIES:
:CUSTOM_ID: clearpage
:END:

The ~clearpage~ macro forces a page break in all supported export backends.

In LaTeX, it also flushes pending floats before starting the new page.

In HTML, the page break is not visible on screen, but it is applied when
printing.

*** Code

#+begin_src org
,#+MACRO: clearpage @@latex:\clearpage@@ @@html:<div style="page-break-after: always;">&nbsp;</div>@@ @@odt:<text:p text:style-name="PageBreak"/>@@
#+end_src

#+begin_warning
For ODT export, this macro relies on a custom paragraph style named ~PageBreak~.

The ~text:p~ element used by the macro is an OpenDocument Text element. It is only
valid in the context of an ODT document where the ~text~ namespace is declared,
which is normally the case in ~content.xml~ generated by Org-mode.

The ~PageBreak~ paragraph style must be defined in the ~styles.xml~ file of the
generated ODT document.

Add the following style definition:

#+begin_src xml :tangle no
<style:style style:name="PageBreak"
style:family="paragraph"
style:parent-style-name="Text_20_body">
<style:paragraph-properties fo:break-before="page"/>
</style:style>
#+end_src

For details on defining custom ODT styles in Org-mode, see:
[[https://www.gnu.org/software/emacs/manual/html_node/org/Advanced-topics-in-ODT-export.html#Creating-one_002doff-styles][Creating one-off styles]].
#+end_warning

*** Parameters

None.

*** Examples

Insert a forced page break:

#+begin_src org :tangle no
{{{clearpage}}}
#+end_src

*** See also

- [[#pagebreak][pagebreak]] macro
- [[#framebreak][framebreak]] macro

** framebreak macro
:PROPERTIES:
:CUSTOM_ID: framebreak
:END:

The ~framebreak~ (or ~framebreak---~) macro inserts a Beamer frame break.

It is equivalent to the Beamer command ~\framebreak~. It is useful to split
a single frame into multiple slides (multiple overlays) at a precise point.

This macro is intended for Beamer export only. It has no effect for non-Beamer
backends.

*** Code

#+begin_src org
,#+MACRO: framebreak @@beamer:\framebreak@@
,#+MACRO: framebreak--- @@beamer:\framebreak@@
#+end_src

*** Parameters

None.

*** Examples

Insert a frame break inside a frame:

#+begin_src org :tangle no
,* My slide title
:PROPERTIES:
:BEAMER_opt: allowframebreaks
:END:

First part of the frame.

{{{framebreak---}}}

Second part of the same frame (exported as the next slide).
#+end_src

You can also insert multiple breaks:

#+begin_src org :tangle no
Part 1. {{{framebreak}}}
Part 2. {{{framebreak}}}
Part 3.
#+end_src

*** Remarks

For the "split into multiple slides" behavior, Beamer frames typically need the
~allowframebreaks~ option (for example via ~:BEAMER_OPT: allowframebreaks~).

Without ~allowframebreaks~, Beamer may not split the frame as expected.

*** See also

- [[#clearpage][clearpage]] macro
- [[#pagebreak][pagebreak]] macro

** Fnb (Beamer footnote) macro
:PROPERTIES:
:CUSTOM_ID: fnb
:END:

The ~fnb~ macro inserts a raw LaTeX footnote using the ~\footnote{...}~ command.

Unlike Org's native footnotes, this macro bypasses Org's footnote processing and
injects the LaTeX command directly into the exported document.

This is particularly useful in Beamer presentations, where direct control over
footnote rendering may be desirable.

*** Code

#+begin_src org
,#+MACRO: fnb @@latex:\footnote{$1}@@
#+end_src

*** Parameters

| Parameter | Description              |
|-----------+--------------------------|
| =$1=        | Footnote text to insert. |

*** Examples

Insert a footnote in a Beamer slide:

#+begin_src org :tangle no
Here is some text {{{fnb(This is a footnote.)}}}.
#+end_src

which expands to:

#+begin_src org :tangle no
Here is some text @@latex:\footnote{This is a footnote.}@@.
#+end_src

and produces:

#+begin_src latex :tangle no
\footnote{This is a footnote.}
#+end_src

during LaTeX/Beamer export.

*** Advantages

- Full control over the generated LaTeX code.
- Avoids potential issues with Org footnote conversion in Beamer frames.
- Useful when the document is intended exclusively for LaTeX/Beamer PDF output.

*** Limitations

- Produces no output for non-LaTeX export backends.
- Not portable across export formats.

** visfootnote (Beamer overlay footnote) macro
:PROPERTIES:
:CUSTOM_ID: visfootnote
:END:

The ~visfootnote~ macro provides a shortcut for inserting Beamer footnotes that
appear only on specific overlays.

It wraps a custom Beamer command based on ~\visible~ and ~\footnote~, allowing
footnotes to participate in overlay specifications in the same way as other
Beamer content.

This macro is useful when revealing slide content progressively and a footnote
should appear only when the associated content becomes visible.

*** Code

The underlying Beamer command (see =beamer-only.setup=):

#+begin_src latex :tangle no
% Footnote visible only on the specified overlays.
\newcommand<>{\visfootnote}[1]{%
  \visible#2{\footnote#2[frame]{#1}}%
}
#+end_src

The Org macro:

#+begin_src org
,#+MACRO: visfootnote @@beamer:\visfootnote<$1>{$2}@@
#+end_src

*** Parameters

The macro accepts two parameters:

1. An overlay specification.
2. The footnote text.

*** Examples

#+begin_src org :tangle no
Git was created by Linus Torvalds.
{{{visfootnote(2-,Initial development started in 2005.)}}}
#+end_src

Exports to:

#+begin_src latex :tangle no
Git was created by Linus Torvalds.
\visfootnote<2->{Initial development started in 2005.}
#+end_src

The footnote is hidden on the first overlay and becomes visible starting from
overlay 2.

*** Typical Usage

The macro is particularly useful together with progressive disclosure:

#+begin_src org :tangle no
- First point.
- Second point. {{{visfootnote(2,Additional details.)}}}
- Third point.
  #+end_src

This ensures that the footnote appears only when the corresponding item becomes
visible.

*** Overlay Specifications

Any valid Beamer overlay specification may be used:

| Specification | Meaning               |
|---------------+-----------------------|
| ~1~             | Only on overlay 1     |
| ~2~             | Only on overlay 2     |
| ~2-~            | From overlay 2 onward |
| ~3-5~           | Overlays 3 through 5  |
| ~1,3~           | Overlays 1 and 3      |

For example:

#+begin_src org :tangle no
{{{visfootnote(3-5,Visible on overlays 3 to 5.)}}}
#+end_src

*** Important

The macro is intended for Beamer export only.

When exporting to non-Beamer backends, the macro expands to nothing because it
relies on Beamer-specific overlay commands.

The macro should be used only when a footnote must follow overlay visibility.
For ordinary footnotes that are always visible, standard Org footnotes remain
the preferred solution.

** Kbd macro
:PROPERTIES:
:CUSTOM_ID: kbd
:END:

The ~kbd~ macro formats an inline command, keyboard shortcut, or shell fragment.

It provides a consistent rendering across LaTeX/PDF and HTML exports.

*** Code

#+begin_src org
,#+HTML_HEAD: <style>
,#+HTML_HEAD: kbd.kbd {background:#eee;border:none;padding:0 .25em}
,#+HTML_HEAD: </style>

#+end_src

For LaTeX or PDF export, the ~latex-listings.setup~ setup file must be loaded, as

#+begin_src org :tangle no

#+end_src

must be marked as ~fragile~ because the underlying implementation relies on

A convenient way is to enable fragile frames globally in the document:

#+begin_src org :tangle no

#+end_src

*** Parameters

1. Text to display.

*** Examples

#+begin_src org :tangle no
Press {{{kbd(C-x C-s)}}} to save the buffer.
Use {{{kbd(git status)}}} to display the repository status.
#+end_src

LaTeX export:

- Renders the text using ~\lightcommandbox{...}~ (see ~tcolorbox~)

HTML export:

- Renders ~<kbd>...</kbd>~

** Ikbd macro
:PROPERTIES:
:CUSTOM_ID: ikbd
:END:

The ~ikbd~ macro formats an inline command, keyboard shortcut, or shell fragment
and simultaneously creates an index entry when exporting to LaTeX.

It provides a unified syntax for documenting commands across LaTeX/PDF and HTML
backends.

In LaTeX, it combines ~\index~ and ~\commandbox~.

In HTML, it renders the content using the ~<kbd>~ element.

*** Code

#+begin_src org
,#+HTML_HEAD: <style>
,#+HTML_HEAD: kbd.ikbd {background:#e8f1ff;border:1px solid #4f6fb3;padding:0 .25em}
,#+HTML_HEAD: </style>
,#+MACRO: ikbd @@latex:\index{$1}\commandbox[$2]{$1}@@ @@html:<kbd class="ikbd">$1</kbd>@@
#+end_src

*** Requirements

For LaTeX or PDF export, the ~latex-listings.setup~ setup file must be loaded, as
it defines the ~\commandbox~ command and its required dependencies.

#+begin_src org :tangle no
,#+SETUPFILE: ~/org/setup/latex-listings.setup
#+end_src

When exporting Beamer presentations, frames containing ~ikbd~ or ~kbd~ macros
must be marked as ~fragile~ because the underlying implementation relies on
~\lstinline~.

A convenient way is to enable fragile frames globally in the document:

#+begin_src org :tangle no
,#+BIND: org-beamer-frame-default-options "fragile"
#+end_src

*** Parameters

1. Text to display and index.

2. Optional LaTeX options passed directly to ~\commandbox~.

   This parameter is ignored for HTML export.

   It is primarily intended to customize the underlying ~listings~
   configuration for a specific command, for example when additional
   characters must be treated as part of an identifier.

*** Examples

#+begin_src org :tangle no
Press {{{ikbd(C-c a a)}}} to launch the agenda.

Use {{{ikbd(git status)}}} to display the repository status.

Search aliases with {{{ikbd(grep-aliases,alsoletter={-})}}}.
#+end_src

LaTeX export:

#+begin_src latex :tangle no
Press \index{C-c a a}\commandbox[]{C-c a a} to launch the agenda.

Use \index{git status}\commandbox[]{git status} to display the repository status.

Search aliases with
\index{grep-aliases}\commandbox[alsoletter={-}]{grep-aliases}.
#+end_src

HTML export:

#+begin_src html :tangle no
Press <kbd class="ikbd">C-c a a</kbd> to launch the agenda.

Use <kbd class="ikbd">git status</kbd> to display the repository status.

Search aliases with <kbd class="ikbd">grep-aliases</kbd>.
#+end_src

*** Remarks

The second parameter is LaTeX-specific and is ignored when exporting to HTML.

When omitted, the macro emits ~\commandbox[]...~, which behaves the same as
~\commandbox...~ because the optional argument is empty.

- [[#idx][idx]] macro

** pause (Beamer overlay) macros
:PROPERTIES:
:CUSTOM_ID: pause
:END:

The ~pause~ and ~pausestar~ macros provide shortcuts for inserting inline Beamer
overlay pauses in slides exported with ox-beamer.

They wrap Beamer's ~\pause~ and ~\pause*~ commands using Org's backend-specific
inline export syntax.

These macros simplify the writing of slides where sentences, paragraphs,
examples, or other content should appear progressively, without using lists,
blocks, or explicit overlay specifications.

*** Code

#+begin_src org
,#+MACRO: pause @@beamer:\pause{}@@
,#+MACRO: pausestar @@beamer:\pause*{}@@
#+end_src

*** Parameters

Neither macro accepts parameters.

Each macro performs a direct textual substitution during export to the Beamer
backend.

*** Examples

#+begin_src org :tangle no
First sentence. {{{pause}}}
Second sentence. {{{pause}}}
Third sentence.
#+end_src

Exports to:

#+begin_src latex :tangle no
First sentence. \pause
Second sentence. \pause
Third sentence.
#+end_src

Similarly:

#+begin_src org :tangle no
First sentence. {{{pausestar}}}
Second sentence.
#+end_src

exports to:

#+begin_src latex :tangle no
First sentence. \pause*
Second sentence.
#+end_src

*** Difference between ~pause~ and ~pausestar~

- ~{{{pause}}}~ expands to ~\pause~.
- ~{{{pausestar}}}~ expands to ~\pause*~.

The starred form is provided by Beamer and behaves differently from ~\pause~ in
some overlay situations. Refer to the Beamer User Guide for the precise
semantics and overlay interaction rules.

*** Important

The Beamer ~\pause~ and ~\pause*~ commands should not be used together with frames
configured with:

#+begin_src org :tangle no
:BEAMER_opt: allowframebreaks
#+end_src

The ~allowframebreaks~ option automatically splits long frames across multiple
slides and does not interact reliably with Beamer overlays. When combined with
overlay commands, only part of the frame content may be displayed or exported as
expected.

Choose one of the following approaches:

- Use ~allowframebreaks~ for long static content that must be split automatically
  across several slides.

- Use ~{{{pause}}}~, ~{{{pausestar}}}~, overlay specifications such as ~<+->~, or
  explicit Beamer overlay commands when progressive disclosure is required.

** Toc macro
:PROPERTIES:
:CUSTOM_ID: toc
:END:

Insert a customizable headlines table of contents (TOC) at the macro's location
during export.

*** Code

#+begin_src org
,#+MACRO: toc (eval (concat "#+TOC: headlines " "$1" " " "$2"))
#+end_src

(Where $2 is optional and may contain additional ~#+TOC~ options such as
~local~ or ~:target #CustomID~.)

*** Parameters

1. Number of headline *levels* to include (integer, e.g. ~1~, ~2~, ~3~).
2. (Optional) Extra option(s), such as ~local~ (for relative depth, showing only
   direct children of the current section) or ~:target #CustomID~.

*** Remarks

The ~toc~ macro expands to a full ~#+TOC:~ keyword line, so the table of contents
appears as a block (*can't be inline* within a paragraph of text).

You usually need to disable the default automatic TOC with
~#+OPTIONS: toc:nil~ (or ~org-export-with-toc nil~) to avoid duplication.

This macro is useful for placing TOCs at specific locations, inserting multiple
TOCs, or creating local sub-TOCs.

*** Examples

- Simple global TOC with 3 levels:

  #+begin_src org :tangle no
  ,#+OPTIONS: toc:nil

  {{{toc(3,)}}}
  #+end_src

- Local TOC showing only direct children of a section:

  #+begin_src org :tangle no
  ,* My Section

  {{{toc(1,local)}}}
  #+end_src

  Shows only level-2 children of "My Section".

*** See also

https://orgmode.org/manual/Table-of-Contents.html

** Twitter "Share a link"
:PROPERTIES:
:CUSTOM_ID: twitter-share-link-button
:END:

Add a "Share a link" button to your website.

*** Code

#+begin_src org
,#+MACRO: twitter-share-link-button @@html:<script src="http://platform.twitter.com/widgets.js"></script><a href="https://twitter.com/share" class="twitter-share-button" data-via="$1">Tweet</a>@@
#+end_src

*** Parameters

1. Username.

*** Examples

Insert the Twitter "Share a link" button here:

{{{twitter-share-link-button(f_niessen)}}}

* Others                                                              :noexport:

Keep a library of helpful CSS classes. Useful for debugging, but should be
avoided in the release version (separate markup and presentation). Since you
can use multiple class names (i.e. ~<p class="floatLeft alignLeft
width75">...</p>~), make use of them debugging your markup.

#+begin_src css :tangle no
.width100 { width: 100%; }
.width75 { width: 75%; }
.width50 { width: 50%; }
.floatLeft { float: left; }
.floatRight { float: right; }
.alignLeft { text-align: left; }
.alignRight { text-align: right; }

.clear         { clear: both; }
.float-left    { float: left; }
.float-right   { float: right; }

.highlight     { background: #FFFFCC; }

.wrap          { width: 960px; margin: 0 auto; }

.img-left      { float: left; margin: 4px 10px 4px 0; }
.img-right     { float: right; margin: 4px 0 4px 10px; }

.nopadding     { padding: 0; }
.noindent      { margin-left: 0; padding-left: 0; }
.nobullet      { list-style: none; list-style-image: none; }
#+end_src
